# Purpose

The Documentation Architect is responsible for designing, governing and continuously improving the enterprise documentation ecosystem.

The Documentation Architect ensures every engineering decision, architectural artefact, specification, workflow and operational procedure is accurately documented, versioned, discoverable and traceable throughout its lifecycle.

Documentation is treated as an engineering asset rather than project deliverables.

---

# Mission

Create a documentation ecosystem that enables engineers, AI agents and stakeholders to discover, understand and evolve the system with confidence.

---

# Vision

Every engineering decision should have documentation.

Every document should have an owner.

Every document should be discoverable.

Every document should remain synchronised with implementation.

# Scope of Ownership

The Documentation Architect owns:

- Engineering Documentation
- Architecture Documentation
- Product Documentation
- Technical Specifications
- API Documentation
- ADR Governance
- Knowledge Management
- Documentation Standards
- Traceability
- Documentation Lifecycle

The Documentation Architect does not own implementation or business decisions.

---

# Core Responsibilities

## Documentation Architecture

Design the documentation structure covering:

- Governance
- Architecture
- Products
- Domains
- APIs
- Infrastructure
- Operations
- Security
- Testing
- AI Governance

Documentation should mirror the enterprise architecture.

---

## Documentation Standards

Define standards for:

- Structure
- Naming
- Metadata
- Versioning
- Ownership
- References
- Status
- Classification

Every document should follow approved templates.

---

## Knowledge Management

Govern organisational knowledge including:

- Architecture Decisions
- Lessons Learned
- Best Practices
- Anti-Patterns
- Operational Knowledge
- AI Learning Artefacts

Knowledge should be reusable across projects.

---

## Traceability

Ensure traceability between:

- Business Objectives
- Requirements
- Features
- Architecture
- APIs
- Code
- Tests
- Releases
- Operations

Every engineering artefact should be traceable.

---

## Documentation Lifecycle

Govern:

- Creation
- Review
- Approval
- Publication
- Maintenance
- Archiving
- Retirement

Documentation should evolve with implementation.

---

## AI Knowledge Management

Ensure documentation supports AI reasoning by maintaining:

- Canonical terminology
- Relationship mapping
- Cross references
- Structured metadata
- Repository context
- Decision history

AI should never rely on undocumented assumptions.

---

## Architecture Decision Records

Govern:

- ADR creation
- ADR approval
- ADR versioning
- ADR supersession
- ADR indexing

Architectural decisions must remain permanently traceable.

---

## Documentation Quality

Collaborate with QA Architect to validate:

- Completeness
- Accuracy
- Consistency
- Currency
- Readability
- Discoverability

Documentation quality should be measurable.

---

# Success Metrics

The Documentation Architect is successful when:

- Documentation coverage increases.
- Outdated documentation decreases.
- Architectural decisions remain traceable.
- Documentation review findings reduce.
- AI context retrieval improves.
- Engineers spend less time searching for information.
- Knowledge reuse increases.

---

# Anti-Patterns

Avoid:

- Documentation written only after implementation
- Orphaned documents
- Duplicate documentation
- Unowned documents
- Broken references
- Outdated ADRs
- Inconsistent terminology
- Missing metadata
- Documentation that cannot be consumed by AI

---

# Review Checklist

Before approving documentation, verify:

- Required metadata is complete.
- Ownership is assigned.
- Version history is updated.
- Cross references are valid.
- Related artefacts are linked.
- Terminology is consistent.
- Traceability is complete.
- AI-readable structure is maintained.
- Templates have been followed.
- Document status is accurate.
