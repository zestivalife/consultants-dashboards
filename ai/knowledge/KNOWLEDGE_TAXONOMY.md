# Purpose

The Enterprise Knowledge Taxonomy defines the classification framework for every knowledge asset within the Enterprise AI Operating System (EAIOS).

It establishes a common vocabulary, hierarchical structure and semantic categorisation model that enables consistent knowledge organisation, retrieval, governance and AI reasoning.

The taxonomy provides the foundation for:

- Enterprise Knowledge Management
- Retrieval-Augmented Generation (RAG)
- Knowledge Graphs
- AI Memory
- Semantic Search
- Context Engineering
- Multi-Agent Collaboration

Every knowledge asset SHALL conform to this taxonomy.

---

# Objectives

The Enterprise Knowledge Taxonomy SHALL:

- Standardise enterprise terminology.
- Eliminate inconsistent classifications.
- Improve discoverability.
- Enable semantic retrieval.
- Support Knowledge Graph construction.
- Improve AI context selection.
- Reduce ambiguity.
- Improve organisational consistency.
- Enable intelligent automation.
- Support enterprise governance.

# Taxonomy Principles

## Principle 1 — One Canonical Classification

Every knowledge asset SHALL have one primary classification.

Secondary classifications MAY be assigned where appropriate.

---

## Principle 2 — Hierarchical Organisation

Knowledge SHALL be organised hierarchically.

Lower levels SHALL inherit context from higher levels.

---

## Principle 3 — Semantic Classification

Classification SHALL be based on meaning rather than storage location.

---

## Principle 4 — Machine Readability

The taxonomy SHALL support AI reasoning, indexing and retrieval.

---

## Principle 5 — Extensibility

The taxonomy SHALL support future knowledge domains without structural redesign.

# Knowledge Asset Classification

Every knowledge asset SHALL be classified using the following structure:

```
Domain
    │
    ▼
Category
    │
    ▼
Subcategory
    │
    ▼
Knowledge Asset Type
    │
    ▼
Knowledge Asset
```

Example:

```
Engineering

↓

Backend

↓

API

↓

Specification

↓

Authentication API
```

Every knowledge asset SHALL define:

- Category
- Subcategory

- Version
- Status
- Tags
- Keywords
- Lifecycle Stage

Classification SHALL be validated before publication.

---

# Taxonomy Naming Standards

Knowledge names SHALL:

- Be descriptive.
- Use consistent terminology.
- Avoid abbreviations unless standardised.
- Be unique within their category.
- Support semantic search.

---

# Semantic Tags

Knowledge SHALL support semantic tags including:

- Technology
- Product
- Business Capability
- Risk
- Compliance
- Security
- AI
- Architecture
- Customer
- Platform
- Programming Language
- Cloud Provider

Tags SHALL supplement, not replace, taxonomy classification.

---

# AI Retrieval Classification

The taxonomy SHALL support AI retrieval using:

- Domain
- Category
- Subcategory
- Asset Type
- Semantic Tags
- Relationships
- Metadata
- Keywords

AI systems SHALL prioritise taxonomy before free-text similarity.

# Quality Gates

Classification SHALL fail if:

- Domain is missing.
- Category is invalid.
- Asset Type is undefined.
- Naming standards are violated.
- Duplicate classifications exist.
- Metadata is incomplete.
