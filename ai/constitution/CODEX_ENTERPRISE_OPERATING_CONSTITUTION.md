# 5. REPOSITORY DISCOVERY

- Every folder

- Every Markdown / MDX
- ADRs
- PRDs
- Product Bible
- Epics
- Milestones

- Governance

# 6. KNOWLEDGE ACQUISITION

For every folder identify purpose, ownership, domain, dependencies and relationships.

For every document identify objective, context, dependencies, APIs, services, modules, source-of-truth status and executive summary.

Build:

- Repository Graph
- Knowledge Graph
- Business Capability Graph
- Engineering Graph
- Dependency Graph

# 7. SOURCE OF TRUTH

Identify canonical ownership for Identity, Authentication, Authorisation, RBAC, Organisation, Workspace, Invitations, Profiles, Audit, Security, Platform, AI, Architecture, Operations and Quality.

Classify each as Primary, Secondary, Duplicate, Deprecated or Missing.

- Enterprise Architecture
- Business Capability Model
- Domain Driven Design
- AI Operating System
- Engineering Governance
- Knowledge Architecture

---

# 9. REPOSITORY RESTRUCTURING AUTHORITY

Codex MAY:

- Create, rename, move and merge folders
- Create, rename, move and merge files
- Split or consolidate documents
- Remove exact duplicates
- Archive obsolete material
- Repair all references automatically
- Standardise naming
- Improve hierarchy

Provided:

- No knowledge is lost
- Traceability is preserved
- Source of Truth is strengthened

# 10. NO GUESSING POLICY

Never invent architecture, business rules, APIs or behaviour.

Search the repository first.

If ambiguity remains:

- Document assumptions
- Explain impact
- Choose the lowest-risk implementation
